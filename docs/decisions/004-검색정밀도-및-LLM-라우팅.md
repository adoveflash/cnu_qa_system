# 004 — 검색 정밀도 개선 + 스킬 라우팅 키워드→LLM tool-calling

## 결정 사항

DIARY 회고("키워드 기반 tool-calling의 한계")에서 지목한 약점을 코드로 해소한다.

### (1) RAG 검색 정밀도 — `src/rag/retriever.py`

- **제출 파이프라인 기본 모드를 `naive` → `rerank`로 변경.** `build_context`/`retrieve`의
  기본 mode를 `_DEFAULT_MODE`(env `RAG_MODE`, 기본 `rerank`)로 둔다. 기존엔 cross-encoder가
  구현돼 있었지만 Streamlit 슬라이더에서만 켜지고 배치 출력(`chat_output.json`)은 naive로 돌아
  무관 청크가 그대로 출처가 됐다.
- **cross-encoder rerank_score 컷오프 추가**(`_apply_cutoff`, env `RAG_RERANK_MIN` 기본 0.0).
  관련도 낮은 청크를 컨텍스트뿐 아니라 **출처 배지에서도 탈락**시킨다(약학대·경영학부 누수 차단).
  전부 컷오프되면 빈 컨텍스트 → "확인되지 않은 정보" 정직 응답.
- **장학금 부스팅 그룹 추가** + `_BOOST_WEIGHT` 0.08 → 0.15(env `RAG_BOOST_WEIGHT`).
  "장학" 키워드가 어느 그룹에도 없어 부스팅이 0이던 문제 해결(공식 안내 plus_kr 우선).

### (2) 스킬 라우팅 — `src/skills/router.py` 신설

- 키워드 매칭(`registry.detect`) 대신 **LLM(Gemma)이 도구·인자를 직접 선택**한다.
- `Skill`에 `parameters`(JSON 스키마) 추가 → 라우터가 도구 스펙 구성·인자 검증.
- tri-state 반환: 도구선택 / 명시적 도구불필요 / 파싱실패(→키워드 `detect()` 폴백).
- `inference.py`를 `src.tools.*` shim → `src.skills` 직접 사용으로 전환(이중 tool 시스템 정리).

## 검토한 대안

- **검색: 거리 컷오프만(리랭크 없이)** — 싸지만 bge-m3 distance는 cross-collection 비교가
  부정확. cross-encoder가 static/live를 같은 스케일로 점수화 → 정규화까지 동시 해결돼 채택.
- **라우팅: 임베딩 유사도 라우팅(bge-m3)** — DIARY가 제시한 대안. 추가 비용은 적지만 인자
  추론은 못 함. **LLM tool-calling**은 도구 선택 + 인자 추출("기숙사"→location, "내일"→날짜)을
  한 번에 하고 변형·줄임말("1학")을 의미로 인식 → 채택.
- **native chat-template `tools=`** — Gemma는 함수호출 토큰이 약해 파싱 불안정 → 프롬프트
  기반 JSON 출력 + 정규식 추출로 대체(디버그·재현 쉬움).

## 선택 이유

- 맥락 응답(40점)에 가장 직접적인 건 검색 정밀도. 리랭커는 **이미 구현돼 있어** 기본 모드만
  바꾸면 되는 저비용·고효과 레버.
- 라우팅은 사람이 키워드를 무한 하드코딩하던 구조를 LLM 의미 판단으로 대체. 키워드는
  안전망(폴백)으로만 남겨 회귀 위험 최소화.
